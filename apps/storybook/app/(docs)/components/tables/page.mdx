## Usage

```tsx
import {
  Table,
  TableBody,
  TableCaption,
  TableCell,
  TableHead,
  TableHeadCell,
  TableRow,
} from "@stefan-florescu/ui";
```

```tsx
<Table>
  <TableCaption>Products</TableCaption>
  <TableHead>
    <TableHeadCell>Product name</TableHeadCell>
    <TableHeadCell>Price</TableHeadCell>
  </TableHead>
  <TableBody>
    <TableRow>
      <TableHeadCell scope="row">Magic Mouse 2</TableHeadCell>
      <TableCell>$99</TableCell>
    </TableRow>
  </TableBody>
</Table>
```

`Table` renders a native `<table>` inside Flowbite's bordered card. Put the column headers directly
in `TableHead` (they are wrapped in one row), and start each body row with a
`TableHeadCell scope="row"` so screen readers announce it with every cell of the row. Give every
table a `TableCaption`, visible or `visuallyHidden`. The parts are server components; only the
horizontal scroller runs on the client.

## Table layout

Show the head, foot or caption of the table.

### Table head (sortable)

Make a column sortable by putting a button in its header, and set `aria-sort` (`ascending` or
`descending`) on the header of the column that orders the rows. The icon shows the direction.

<ComponentPreview name="table-sortable" />

### Table foot

`TableFoot` renders a `<tfoot>` for totals: Flowbite's semibold `heading` row with a `text-base`
label. Put the cells directly inside. This example has no border and a `rounded` head.

<ComponentPreview name="table-foot" />

### Table caption

`TableCaption` titles the table. It is read when screen-reader users reach the table, and names the
table's scroller. Add a `description` for supporting text, or `visuallyHidden` to keep the caption
for screen readers only, as every other example on this page does.

A table wider than its container scrolls sideways (WCAG 1.4.10 Reflow). When it overflows, the
scroller joins the tab order and becomes a region named by the caption, so keyboard users can scroll
it with the arrow keys. Try it with <Kbd>Tab</Kbd>.

## Accessibility

- Renders a native `<table>` with `<caption>`, `<thead>`, `<tbody>` and `<tfoot>`: screen readers
  announce its size and move by row and column with their table commands. Pattern:
  [WAI-ARIA Table](https://www.w3.org/WAI/ARIA/apg/patterns/table/).
- `TableHeadCell` is a `<th scope="col">` in the head; with `scope="row"` it heads a row, so each cell
  is announced with its row and column headers. Flowbite's examples use the same scopes.
- Give every table a caption. `TableCaption visuallyHidden` keeps it for screen readers only.
  Flowbite captions only its "Table caption" example; every example here has one.
- **Scrolling.** A table wider than its container scrolls sideways instead of making the page
  scroll (WCAG 1.4.10). While it overflows, the scroller has `tabindex="0"` and `role="region"`, named
  by the caption title (or the table's `aria-label`), so it can be scrolled with the arrow keys (WCAG
  2.1.1) and shows the solid focus outline. Flowbite's scroller cannot take focus.
- Sortable columns put a real button in the header and set `aria-sort` on the sorted column.
  Flowbite's sort icons are links with no text.
- Repeated actions ("Edit", "Remove", "Edit user") add the row's name as visually hidden text, so
  each link or button has a unique name out of context.
- Row checkboxes are named after their row ("Select Magic Mouse 2"); Flowbite names them all "Table
  checkbox". The select-all checkbox is indeterminate (announced as mixed) while only some rows are
  selected.
- Search and filter results are announced through a visually hidden status ("4 products").
- Contrast passes WCAG 2.2 AA in both themes. One change from Flowbite: in dark mode the brand table's
  body text is `brand-foreground` (white) instead of `fg-brand-subtle`, which is 3.7:1 on the dark
  `brand` fill.
- Rows only change colour on hover; a row is never a click target of its own. Put the action in a cell
  as a link or button.

| Key                       | Action                                                       |
| ------------------------- | ------------------------------------------------------------ |
| <Kbd>Tab</Kbd>            | Moves to the next link, button or field in the table         |
| <Kbd>Tab</Kbd>            | Moves to the scroller when the table is wider than its space |
| <Kbd>←</Kbd> <Kbd>→</Kbd> | Scroll the focused scroller sideways                         |

## API Reference

### Table

| Prop                 | Type                                | Default     |
| -------------------- | ----------------------------------- | ----------- |
| `variant`            | `"default" \| "brand"`              | `"default"` |
| `striped`            | `boolean \| "rows" \| "columns"`    | `false`     |
| `hoverable`          | `boolean`                           | `false`     |
| `bordered`           | `boolean`                           | `true`      |
| `shadow`             | `boolean`. Only with `bordered`.    | `true`      |
| `rounded`            | `boolean`. Only without `bordered`. | `false`     |
| `toolbar`            | `ReactNode`, shown above the table  | —           |
| `footer`             | `ReactNode`, shown under the table  | —           |
| `containerClassName` | `string`, for the card              | —           |
| `className`          | `string`, for the `<table>`         | —           |

All other `<table>` attributes are forwarded to the `<table>`, including `ref` and `aria-label`.

### TableCaption

| Prop             | Type                         | Default |
| ---------------- | ---------------------------- | ------- |
| `description`    | `ReactNode`, under the title | —       |
| `visuallyHidden` | `boolean`                    | `false` |

### TableHeadCell

| Prop    | Type                                         | Default |
| ------- | -------------------------------------------- | ------- |
| `scope` | `"col" \| "row" \| "colgroup" \| "rowgroup"` | `"col"` |

### TableHead, TableBody, TableRow, TableCell, TableFoot

Render `<thead>`, `<tbody>`, `<tr>`, `<td>` and `<tfoot>`, and forward their native attributes.
`TableHead` and `TableFoot` wrap cells in a row; pass `<tr>` elements for several rows. Row fills,
stripes and hover come from the `Table`; a `className` on a part overrides them.
