Colour is built in two layers. **Primitives** are the raw palette: every hue in eleven steps.
**Semantic tokens** give those values a purpose — `text-heading`, `bg-brand`, `border-default` — and
each theme re-assigns them. Components only ever use semantic tokens, so a new theme never
requires a code change.

## Default colors

Twenty-two palettes, each with eleven steps from `50` (lightest) to `950` (darkest), defined in
OKLCH for perceptually even steps. They follow the Tailwind CSS v4 defaults used by Flowbite.
Every step is available as a CSS variable, for example `--sds-color-blue-700`.

## When to use

### Text

- `text-heading` for titles and key figures; `text-body` for all running text.
- `text-body-subtle` for secondary information only — never for essential content.
- `text-brand` for links and brand accents. Pair coloured status text with its soft background
  (`text-danger` on `bg-danger-soft`).
- `text-on-brand` on any solid `bg-brand`, `bg-success` or `bg-danger` surface.

### Background

- `bg-default` is the page. Layer neutral surfaces upwards with `bg-subtle` → `bg-muted` →
  `bg-emphasis`; each step adds emphasis (hover, selected).
- `bg-brand` for the single most important action in a view; `bg-brand-strong` for its hover
  and pressed states.
- Soft status backgrounds (`bg-success-soft`, `bg-danger-soft`, `bg-warning-soft`,
  `bg-brand-soft`) for alerts, badges and highlights.
- `bg-inverse` for small, high-contrast surfaces such as tooltips.

### Border

- `border-default` for cards, tables and dividers; `border-subtle` inside a surface;
  `border-strong` between surfaces.
- `border-control` for the edges of inputs, selects and checkboxes, so users can find them.
- `border-focus` (or `ring-focus`) for every focus indicator.
- Status borders frame their matching soft background.

### Avoid

- Primitive colours (`blue-700`, `gray-200`) in components or product code.
- Status colours used as decoration — red always means danger, green always means success.
- Meaning carried by colour alone. Add an icon, a label or a pattern.

## Theming with tokens

### 1. Import the styles

The UI styles include the tokens, both themes and the Tailwind utilities.

```css
/* app/globals.css */
@import "tailwindcss";
@import "@stefan-florescu/ui/styles.css";
```

Not using Tailwind? Import the CSS variables directly:

```css
@import "@stefan-florescu/tokens/css";
@import "@stefan-florescu/themes/css";
```

### 2. Choose a theme

Light is the default. Set `data-theme` on `<html>` — or on any element to theme just that part
of the page.

```html
<html data-theme="dark">
  <!-- the whole app is dark -->
</html>

<section data-theme="light">
  <!-- this section stays light inside a dark page -->
</section>
```

### 3. Use semantic tokens

```tsx
export function Notice() {
  return (
    <div className="border-default bg-subtle rounded-lg border p-4">
      <h3 className="text-heading font-semibold">Payment received</h3>
      <p className="text-body">Your invoice has been paid.</p>
      <button className="bg-brand text-on-brand hover:bg-brand-strong focus-visible:outline-focus rounded-md px-4 py-2 focus-visible:outline-2">
        View invoice
      </button>
    </div>
  );
}
```

The same tokens are available as CSS variables:

```css
.notice {
  background: var(--sds-color-background-subtle);
  color: var(--sds-color-text-body);
  border: 1px solid var(--sds-color-border-default);
}
```

### 4. Switch themes at runtime

Themes are pure CSS, so switching is instant and needs no re-render. In Next.js, `next-themes`
manages the attribute, the user's preference and the system setting:

```tsx
"use client";

import { ThemeProvider } from "next-themes";

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <ThemeProvider attribute="data-theme" defaultTheme="system" enableSystem>
      {children}
    </ThemeProvider>
  );
}
```

### 5. Create a custom theme

A theme only re-assigns semantic tokens. Add a folder to `packages/themes/src/` and it is built
as `[data-theme="<name>"]`, contrast-checked, and published with the other themes.

```jsonc
// packages/themes/src/ocean/color.json
{
  "color": {
    "$type": "color",
    "background": {
      "brand": { "$value": "{color.cyan.700}" },
      "brand-strong": { "$value": "{color.cyan.800}" },
    },
    "text": {
      "brand": { "$value": "{color.cyan.700}" },
    },
  },
}
```

## Accessibility

Every colour pairing must meet [WCAG 2.2](https://www.w3.org/TR/WCAG22/) level AA in every theme:

- **Text** — at least **4.5:1** against its background (3:1 for text 24px and larger, or 18.7px
  bold).
- **Non-text** — focus indicators and the boundaries of form controls need at least **3:1**
  against adjacent colours.
- **Never rely on colour alone** — errors need a message and an icon, links in running text need
  an underline, charts need labels or patterns.
- **Disabled** elements are exempt from contrast requirements, but must still look clearly
  disabled.
- **Check both themes** — a pairing that passes in light mode can fail in dark mode.

### Verified pairings

These pairings are checked automatically on every build of `@stefan-florescu/themes`. If a token
change pushes any of them below its minimum in any theme, the build fails.
