| Variant    | Look                                                                       | Use it for                                   |
| ---------- | -------------------------------------------------------------------------- | -------------------------------------------- |
| `default`  | Box and label                                                              | Most forms.                                  |
| `bordered` | `neutral-primary-soft` card with a `default` border, `rounded-base`        | Options that need a larger click target.     |
| `list`     | Row of a list group; the label fills the row                               | Several options inside one bordered list.    |
| `card`     | Selectable card; `brand-softer` fill, `brand` border and `fg-brand-strong` | Rich options with an icon and a description. |

## Accessibility

- A native `<input type="checkbox">`, so <kbd>Space</kbd> toggles it, forms submit it and assistive
  technology announces it as a checkbox. The label is linked to it, so clicking the label toggles it.
- The box is drawn with Flowbite's styles, with one change: its border is the `input` colour
  instead of Flowbite's `default-medium`, so the unchecked box reaches 3:1 against the page
  (WCAG 1.4.11). Checked, it is `brand` with a `brand-foreground` check mark.
- Focus shows Flowbite's soft `brand-soft` halo; keyboard focus also draws a solid 2px `ring`
  outline, because the halo alone is under 3:1.
- In forced-colors (high contrast) mode the browser draws the checkbox itself, so it stays visible.
- In bordered cards with a description, and in `card`, the title names the checkbox and the
  description is read as its description.
- `card` keeps the checkbox focusable (Flowbite hides it with `display: none`, which removes it from
  the keyboard order), and the selected card gets a `brand` border instead of Flowbite's
  `brand-subtle`, so the checked state reaches 3:1.
- The link in a label is underlined, not only coloured, so it does not rely on colour alone
  (WCAG 1.4.1).
- `invalid` sets `aria-invalid` and a `danger` border; explain the problem in text as well.
- In the checkbox dropdown, the panel is a non-modal dialog named "Users"; <kbd>Escape</kbd> or a
  click outside closes it and returns focus to the trigger. Flowbite's search field has no label;
  here it is labelled "Search user", and choices are kept while the search hides them.
- Not ported: Flowbite's _Colors_ (uses palette colours we have no tokens for; a red or green
  checkbox would also read as an error or success).

## API Reference

### Checkbox

| Prop          | Type                                          | Default     |
| ------------- | --------------------------------------------- | ----------- |
| `label`       | `ReactNode`                                   | —           |
| `description` | `ReactNode`                                   | —           |
| `variant`     | `"default" \| "bordered" \| "list" \| "card"` | `"default"` |
| `icon`        | `ReactNode` (for `bordered` and `card`)       | —           |
| `endIcon`     | `ReactNode` (end of a `card`)                 | —           |
| `invalid`     | `boolean`                                     | `false`     |

All other `<input>` attributes are forwarded, such as `name`, `value`, `checked`, `defaultChecked`
and `disabled`. `className` styles the outer element.
