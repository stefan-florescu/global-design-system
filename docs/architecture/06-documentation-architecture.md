# 06 · Documentation Architecture

> **Current state:** the docs site lives in `apps/storybook` (the folder keeps that name; it is a
> Next.js site, not the Storybook tool — see ADR 0006). It has the Foundation, Components and
> Changelog sections; the remaining sections below are added as content exists.

## 6.1 One surface

| Surface       | App              | Audience                          | Content                                                   |
| ------------- | ---------------- | --------------------------------- | --------------------------------------------------------- |
| **Docs site** | `apps/storybook` | Designers, PMs, engineers, agents | Guidance, live examples (Preview / Code), props, patterns |

Live examples are real source files (`registry/demos/*.tsx`) rendered from the published package,
and the Code tab shows exactly that source, so docs cannot drift from code. Props tables and token
tables will be generated from TypeScript types and `@stefan-florescu/tokens`.

## 6.2 Information architecture (docs site)

```
/                                    Home — what, why, quick start
/getting-started
  /installation   /usage-nextjs   /usage-vite   /theming   /figma
/foundations
  /color  /typography  /spacing  /radius  /elevation  /grid  /breakpoints
  /motion  /iconography  /focus
/components
  /<component>                       (one page per component, template below)
/patterns
  /<pattern>
/templates
  /<template>
/accessibility
  /principles  /checklist  /keyboard  /screen-readers  /testing  /conformance
/content
  /voice-and-tone  /grammar  /capitalisation  /errors  /empty-states  /actions-and-labels  /inclusive-language
/decisions                           ADRs rendered from docs/decisions
/releases
  /changelog  /migration/<v>  /roadmap
```

Source mapping: `apps/docs/content/<section>/*.mdx` for guidance; component pages pull
`packages/ui/src/components/<name>/<name>.mdx` + `.meta.json`; `/decisions` renders `docs/decisions/*.md`;
`/releases/changelog` renders package `CHANGELOG.md`s.

## 6.3 Page templates

**Foundation page:** Overview · Principles · Scale/tokens table (generated from `tokens.json`) ·
Usage do/don't · Accessibility · Tailwind usage · Related.

**Component page:**

1. Header — name, one-line description, status badge, links (source, Figma)
2. Preview — live example with code tab
3. Usage — when to use / when not to use / alternatives
4. Anatomy — labelled diagram
5. Variants & sizes — live examples
6. States — hover, focus, active, disabled, loading, invalid
7. Content guidelines — labels, length, tone
8. Accessibility — ARIA pattern, keyboard map table, SR behaviour
9. API — props table (generated from TS types + TSDoc)
10. Tokens — component tokens consumed (generated)
11. Related components & patterns · Changelog for this component

**Pattern page:** Problem · Solution · Anatomy · Components used · Variations · Do/Don't · Code recipe.

**ADR:** Context · Decision · Consequences · Alternatives · Status (template in `docs/decisions/0000-template.md`).

**Release notes:** generated by Changesets per package; curated highlights + migration guide per minor/major.

## 6.4 Accessibility documentation

- Target: **WCAG 2.2 AA** (AAA contrast for body text where feasible).
- Each component documents its keyboard map and screen-reader expectations.
- `/accessibility/conformance` tracks per-component status (tested AT/browser matrix).

## 6.5 Docs tooling roadmap

- MDX via `@next/mdx` or Fumadocs/Contentlayer-style loader (ADR when Phase A starts).
- Props tables: `react-docgen-typescript`.
- Token tables: imported from `@stefan-florescu/tokens/json`.
- Search: Pagefind / Algolia DocSearch.
- `llms.txt` + `llms-full.txt` and per-page `.md` endpoints for AI consumption (see 07).
